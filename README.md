# Solana Escrow

Escrow-проект на Solana, написанный с использованием Rust и Anchor.

Проект позволяет двум пользователям обмениваться SPL-токенами через смарт-контракт без необходимости доверять третьей стороне.

## Идея проекта

Идея проекта появилась из личного опыта.

Когда-то я сам пользовался услугами escrow-сервиса, но в том случае escrow был не смарт-контрактом, а обычным человеком-посредником. Обе стороны сделки доверяли ему активы, а за проведение обмена он брал комиссию.

Мне стало интересно, как можно реализовать похожий механизм без необходимости доверять конкретному человеку.

Так появилась идея реализовать escrow через Solana, где условия сделки контролируются программой, а обмен выполняется атомарно.

## Как работает проект

В сделке участвуют две стороны:

- **Sender** — создаёт сделку и блокирует свои токены в escrow.
- **Receiver** — может принять или отклонить предложенную сделку.

Для каждой сделки создаётся PDA `Holder`, который хранит условия сделки и является authority для escrow token account.

## Создание сделки

Sender указывает:

- адрес Receiver;
- mint токена, который хочет отправить;
- количество отправляемых токенов;
- mint токена, который хочет получить;
- количество токенов, которое хочет получить.

После создания сделки программа:

1. Создаёт `Holder PDA`.
2. Создаёт Associated Token Account для Holder.
3. Переводит токены Sender в этот token account.
4. Сохраняет условия сделки в `Holder`.

После этого токены находятся под контролем программы.

## Holder PDA

Holder PDA вычисляется из:

```rust
[
    b"ESCROW",
    sender.key().as_ref(),
    receiver.key().as_ref(),
]
```

В текущей реализации это означает, что между одной парой `Sender / Receiver` одновременно может существовать только одна активная сделка.

## Принятие сделки

Receiver может загрузить сделку и посмотреть её условия.

Если Receiver принимает сделку, программа в рамках одной транзакции:

1. Переводит требуемые токены от Receiver к Sender.
2. Переводит токены из Holder ATA к Receiver.
3. Закрывает Holder ATA.
4. Закрывает Holder PDA.

Сделка выполняется атомарно.

То есть либо выполняются все операции, либо вся транзакция откатывается.

После успешного обмена временные escrow-аккаунты закрываются.

## Отклонение сделки

Receiver также может отказаться от сделки.

В этом случае:

1. Заблокированные токены возвращаются Sender.
2. Holder ATA закрывается.
3. Holder PDA закрывается.

То есть Sender снова получает свои токены, если Receiver не хочет участвовать в обмене.

## Закрытие аккаунтов

После завершения сделки временные escrow accounts больше не нужны.

Поэтому программа закрывает:

- Holder token account;
- Holder PDA.

Это позволяет вернуть SOL, использованные для rent.

Обычные пользовательские ATA при этом не закрываются.

## Используемые технологии

- Rust

- SPL Token Program

- React

AI использовался как инструмент и помощник во время разработки frontend части:

- построение клиентских транзакций;

Для работы с проектом понадобятся:

- Rust;

